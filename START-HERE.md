## Background: What Is This Project?

This repo demonstrates **Chainlink DECO** — a protocol that lets you prove facts about web data (like "this person passed an identity check") without revealing the underlying data. The proof is called an **attestation**.

The Node-centric demo verifies a DECO attestation and writes the result (`PASS` or `FAIL`) to the Sepolia blockchain. It has three components that talk to each other:

```
Chainlink Node (Docker, port 6688)
    │  receives a trigger, calls the bridge
    ▼
External Adapter (your machine, port 8788)
    │  asks prover-api to verify, then sends a transaction
    ▼
Prover API (your machine, port 8787)
    │  reads attestation files from disk, verifies signature + predicates
    ▼
Sepolia Blockchain
    transaction data contains "PASS|0x<proofId>"
```

For a deeper architectural overview, read `DEMO-README.md`. If any section is unclear, paste it into GPT or Claude and ask for an explanation (the doc itself was generated by Claude Opus, so it's thorough but dense).

## Part A: Generate Your DECO Attestation Files

Before running the demo, you need two attestation files. The repo already includes sample files, so you can skip to Part B if you just want to test the flow. But if you want to generate fresh ones:

### A1. Create a Persona Sandbox Account

1. Go to the Persona sandbox credentials page:
   https://deco.chain.link/sandbox/docs/oauth-tokens#persona-sandbox-credentials
2. Follow the instructions to create an account and obtain your sandbox API credentials.
3. Keep your credentials handy — you need them in the next step.

### A2. Run a DECO Identity Check

1. Follow this guide end-to-end:
   https://deco.chain.link/sandbox/docs/identity-check-persona
2. This walks you through triggering an identity verification using Chainlink DECO in their sandbox.

### A3. Export the Attestation Files

After the identity check completes, you need to download the results and place them in this repo:

1. In the DECO Sandbox, go to the **Runs** section.
2. Find the run you just completed and open it.
3. Download these two files:
   - `json-encoded-attestation.json` — the raw attestation with the ECDSA signature
   - `decoded-attested-data.json` — the decoded data showing which predicates passed
4. Copy both files into the **root** of this repository (i.e. the same directory as this `START-HERE.md` file):
   ```bash
   # Example — adjust the source path to wherever your browser downloaded them
   cp ~/Downloads/json-encoded-attestation.json .
   cp ~/Downloads/decoded-attested-data.json .
   ```
5. Verify they're in the right place:
   ```bash
   ls json-encoded-attestation.json decoded-attested-data.json
   ```
   You should see both files listed with no errors.

These are the files the Prover API reads to verify the attestation. Without them in the repo root, the demo will fail.

## Part B: Configure Everything

You need to create three config files before anything will start. None of them exist yet — only their `.example` templates do.

### B1. Chainlink Node `.env`

```bash
cd chainlink-node
cp .env.example .env
```

Open `chainlink-node/.env` and set these values:

```env
POSTGRES_USER=postgres
POSTGRES_PASSWORD=mysecretpassword
POSTGRES_DB=chainlink

CHAINLINK_API_EMAIL=admin@pixelette.local
CHAINLINK_API_PASSWORD=PixeletteChainlink2024!

KEYSTORE_PASSWORD=KeystorePass123456
```

> **Important:** The `CHAINLINK_API_EMAIL` and `CHAINLINK_API_PASSWORD` values above match what `trigger-job.sh` expects. If you change them, update that script too.
>
> **Important:** `CHAINLINK_API_PASSWORD` must be at least 16 characters.
>
> You do NOT need to set `ALCHEMY_API_KEY` or `INFURA_PROJECT_ID`. The RPC URL is already hardcoded in `config/config.toml` pointing to a ValidationCloud endpoint.

### B2. Chainlink Node `secrets.toml`

```bash
cd chainlink-node/config
cp secrets.toml.example secrets.toml
```

Open `chainlink-node/config/secrets.toml` and fill in the password you chose above:

```toml
[Database]
URL = 'postgresql://postgres:mysecretpassword@postgres:5432/chainlink?sslmode=disable'

[Password]
Keystore = 'KeystorePass123456'
```

> The `YOUR_POSTGRES_PASSWORD` in the URL must match `POSTGRES_PASSWORD` from your `.env` file exactly.

### B3. Chainlink Node `api.txt`

Create the file `chainlink-node/config/api.txt` with exactly two lines — the email on line 1, the password on line 2:

```
admin@pixelette.local
PixeletteChainlink2024!
```

> These must match the `CHAINLINK_API_EMAIL` and `CHAINLINK_API_PASSWORD` from your `.env`.

### B4. External Adapter `.env`

```bash
cd chainlink-node/external-adapter
cp .env.example .env
```

Open `chainlink-node/external-adapter/.env` and set your private key:

```env
EA_PORT=8788
PROVER_API_URL=http://localhost:8787
PRIVATE_KEY=0xYOUR_PRIVATE_KEY_HERE
SEPOLIA_RPC_URL=https://sepolia.ethereum.validationcloud.io/v1/lll0Mm6Ti3NvCS1etac3ZwBpdVutGaNLyYjjjQn-YHg
```

> **Critical:** `PRIVATE_KEY` is the only value you must change. It must be a hex-encoded Ethereum private key with a `0x` prefix, and the corresponding wallet must have Sepolia ETH for gas. The adapter will refuse to start without it.
>
> The other values can stay as defaults.

### B5. Prover API

The Prover API has no `.env` file and no environment variables. It reads attestation files from the repo root using relative paths. No configuration needed.

### Config Checklist

Before moving on, confirm you have created all of these:

- [ ] `chainlink-node/.env`
- [ ] `chainlink-node/config/secrets.toml`
- [ ] `chainlink-node/config/api.txt`
- [ ] `chainlink-node/external-adapter/.env` (with your real private key)
- [ ] Attestation files exist at repo root: `json-encoded-attestation.json` and `decoded-attested-data.json`

## Part C: Start All Three Services

You need three terminals. Start them in this order because each service depends on the one before it.

### C1. Start the Chainlink Node (Terminal 1)

```bash
# Make sure Docker is running first!
# macOS: open -a Docker

cd chainlink-node
docker compose up -d
```

Watch the logs and wait for the node to finish booting:

```bash
docker logs chainlink-node -f
```

You're looking for these two lines in the output:

```
Chainlink booted in X.XXs
Listening and serving HTTP on 0.0.0.0:6688
```

This can take 30-60 seconds on first boot. Once you see those lines, press `Ctrl+C` to stop tailing logs (the node keeps running in the background).

> **If it fails:** Check that Docker is running, and that your `config/secrets.toml` password matches your `.env` `POSTGRES_PASSWORD`.

### C2. Start the Prover API (Terminal 2)

Open a new terminal:

```bash
cd prover-api
npm install
npm run dev
```

You should see:

```
prover-api listening on http://127.0.0.1:8787
```

> **Gotcha:** You must run this from inside the `prover-api/` directory. It finds the attestation files by looking one directory up from its working directory (`../json-encoded-attestation.json`). Running it from anywhere else will break file loading.

### C3. Start the External Adapter (Terminal 3)

Open a new terminal:

```bash
cd chainlink-node/external-adapter
npm install
npm run dev
```

You should see:

```
DECO External Adapter running on http://localhost:8788
Wallet address: 0x<your wallet address>
Prover API URL: http://localhost:8787
```

> **If it exits immediately:** Your `PRIVATE_KEY` is missing or malformed in the `.env` file.

## Part D: Configure the Chainlink Node UI

Now that all three services are running, you need to tell the Chainlink Node how to reach the External Adapter and what job to run.

### D1. Log In

1. Open http://localhost:6688 in your browser
2. Log in with:
   - **Email:** `admin@pixelette.local`
   - **Password:** `PixeletteChainlink2024!`

### D2. Create the Bridge

The bridge tells the Chainlink Node where the External Adapter lives.

1. In the left sidebar, click **Bridges**
2. Click **New Bridge**
3. Fill in:
   - **Name:** `deco-adapter`
   - **URL:** `http://host.docker.internal:8788`
   - **Confirmations:** `0`
   - **Minimum Contract Payment:** `0`
4. Click **Create Bridge**

> **Why `host.docker.internal` instead of `localhost`?** The Chainlink Node runs inside a Docker container. From inside the container, `localhost` refers to the container itself, not your machine. `host.docker.internal` is a special Docker hostname that points back to your host machine where the External Adapter is running.

### D3. Create the Job

The job defines the pipeline — when triggered, it calls the bridge and parses the result.

1. In the left sidebar, click **Jobs**
2. Click **New Job**
3. Paste this TOML (also found in `chainlink-node/jobs/deco-verification-job.toml`):

```toml
type = "webhook"
schemaVersion = 1
name = "deco-verification"
externalJobID = "a1b2c3d4-e5f6-7890-abcd-ef1234567890"

observationSource = """
    fetch_and_verify [type="bridge" name="deco-adapter" requestData="{\\"id\\": \\"deco-verify\\", \\"data\\": {}}"]

    parse_result [type="jsonparse" path="data,txHash" data="$(fetch_and_verify)"]

    fetch_and_verify -> parse_result
"""
```

4. Click **Create Job**

What this does:
- `fetch_and_verify` calls the `deco-adapter` bridge (your External Adapter at `:8788`)
- `parse_result` extracts the `txHash` from the adapter's response
- The `->` arrow defines the execution order

## Part E: Run the Demo

Everything is configured. Pick one of three ways to trigger the verification:

### Option 1: Via the Chainlink Node UI

1. Go to **Jobs** in the sidebar
2. Click on `deco-verification`
3. Click the **Run** button

### Option 2: Via the trigger script

From the repo root:

```bash
chmod +x trigger-job.sh
./trigger-job.sh
```

This script logs into the Chainlink Node API, gets a session cookie, and triggers the webhook job. If you have `jq` installed, the output is nicely formatted.

### Option 3: Hit the External Adapter directly (bypasses Chainlink Node)

This is the fastest way to test — it skips the Chainlink Node entirely and calls the adapter directly:

```bash
curl -X POST http://localhost:8788 \
  -H "Content-Type: application/json" \
  -d '{"id": "test-1", "data": {}}'
```

### What Happens When You Trigger It

1. The External Adapter receives the request
2. It calls `GET http://localhost:8787/deco/verify` on the Prover API
3. The Prover API loads `json-encoded-attestation.json` and `decoded-attested-data.json` from the repo root
4. It verifies the ECDSA secp256k1 signature using `@noble/curves`
5. It checks that all entries in the `success` array are `true`
6. It returns `{ result: "PASS", proofId: "0x..." }` to the adapter
7. The adapter encodes `"PASS|0x<proofId>"` as hex
8. It sends a self-transfer transaction on Sepolia with that hex as calldata (0 ETH value, you only pay gas)
9. It returns the transaction hash

---

## Part F: Verify the Result

A successful response from the External Adapter looks like:

```json
{
  "jobRunID": "test-1",
  "statusCode": 200,
  "data": {
    "result": "0x<transaction_hash>",
    "txHash": "0x<transaction_hash>",
    "proofId": "0xec5d5d9fba2bef6d",
    "verificationResult": "PASS"
  }
}
```

To see the result on-chain:

1. Copy the `txHash` value
2. Go to `https://sepolia.etherscan.io/tx/<txHash>`
3. Scroll down to **Input Data**
4. Click **View as UTF-8**
5. You should see: `PASS|0xec5d5d9fba2bef6d`

## Troubleshooting

### Chainlink Node won't start
```bash
docker logs chainlink-node
```
Common causes: Docker not running, `secrets.toml` password doesn't match `.env`, `api.txt` missing or password under 16 characters.

### External Adapter exits immediately
Your `PRIVATE_KEY` is not set in `chainlink-node/external-adapter/.env`. It must be a hex string starting with `0x`.

### External Adapter can't reach Prover API
Make sure the Prover API is running on port 8787:
```bash
curl http://localhost:8787/health
```

### Bridge call fails from Chainlink Node
The bridge URL must be `http://host.docker.internal:8788`, **not** `http://localhost:8788`. The Chainlink Node runs inside Docker and can't reach `localhost` on your host machine.

### Transaction fails
- Make sure your wallet has Sepolia ETH
- Verify the RPC is reachable:
```bash
curl -X POST https://sepolia.ethereum.validationcloud.io/v1/lll0Mm6Ti3NvCS1etac3ZwBpdVutGaNLyYjjjQn-YHg \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}'
```

### Prover API can't find attestation files
You must `cd prover-api` before running `npm run dev`. The server resolves file paths relative to its working directory (one directory up = repo root). If you run it from elsewhere, it won't find the JSON files.
